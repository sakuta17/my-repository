Q1. Docker Compose – Online Event Management System Using Tomcat and NGINX [25 Marks]
--------------------------------------------------------------------------------

OVERVIEW:
Deploy Tomcat (port 8080) and NGINX (port 80) reverse proxy using Docker Compose.

STEP 1: Create a dedicated working directory
Execute in terminal:
  mkdir -p ~/set1_task1
  cd ~/set1_task1

STEP 2: Create the NGINX configuration file (nginx.conf)
Execute in terminal:
  cat << 'EOF' > nginx.conf
events { worker_connections 1024; }

http {
    upstream tomcat_server {
        server tomcat:8080;
    }

    server {
        listen 80;
        server_name localhost;

        location / {
            proxy_pass http://tomcat_server;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
}
EOF

STEP 3: Create the Docker Compose file (docker-compose.yml)
Execute in terminal:
  cat << 'EOF' > docker-compose.yml
version: '3.8'

services:
  tomcat:
    image: tomcat:9.0-jdk11-openjdk-slim
    container_name: oems-tomcat
    restart: always
    ports:
      - "8080:8080"
    networks:
      - oems-network

  nginx:
    image: nginx:alpine
    container_name: oems-nginx
    restart: always
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - tomcat
    networks:
      - oems-network

networks:
  oems-network:
    driver: bridge
EOF

STEP 4: Run the Docker Compose application
Execute in terminal:
  docker compose up -d

STEP 5: Verification commands
  docker compose ps
  docker network ls
  docker network inspect set1_task1_oems-network
  docker compose logs nginx
  docker compose logs tomcat

STEP 6: Test in browser or curl
  curl -I http://localhost
  # Or open browser: http://localhost:80

WHAT TO SHOW TO MAM:
1. Terminal: Run `docker compose ps`. Show both `oems-tomcat` (port 8080) and `oems-nginx` (port 80) with status "Up".
2. Terminal: Run `docker network inspect <network_name>` to show both containers attached to the custom bridge network `oems-network`.
3. Browser: Open `http://localhost:80` (or `http://<machine-ip>:80`). Show that visiting NGINX on port 80 forwards to Tomcat's default landing page or response.
4. Terminal: Run `docker compose logs nginx` to show HTTP 200/302 access logs from NGINX proxying to Tomcat.

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q1.1: NGINX container unable to communicate with Tomcat container:
  - Cause: Containers not on the same Docker custom network, wrong service name in `nginx.conf` (must use service name `tomcat`, not localhost or container IP), or Tomcat container crashed.
  - Troubleshooting:
    1. Check network: `docker inspect <container_id>` to confirm both share `oems-network`.
    2. Check service name: ping tomcat from nginx using `docker exec -it oems-nginx ping tomcat`.
    3. Check port: Ensure Tomcat is listening on port 8080 inside container.
Q1.2: 502 Bad Gateway error when accessing via NGINX:
  - Cause: Tomcat container is down, still starting up, or listening on a different port than upstream configured in nginx.
  - Troubleshooting:
    1. Check Tomcat status: `docker compose ps` and `docker compose logs tomcat`.
    2. Check upstream address: Verify `proxy_pass http://tomcat:8080;` in `nginx.conf`.
    3. Check Nginx error logs: `docker compose logs nginx` to see "Connection refused".
Q1.3: Port 80 already in use on host machine:
  - Solution: In `docker-compose.yml`, change NGINX host port mapping under `ports:` from `"80:80"` to `"8081:80"` (or `"8090:80"`). The internal container port stays 80, only the host port changes.

Q2. AWS EC2 Deployment – Online Event Management Maven Web Application [25 Marks]

Deploy Maven Web Application (https://github.com/haleema91/LAB-INTERNAL-II-OEMS.git) on AWS Ubuntu EC2 with Tomcat on port 9090.

5. Web Browser: Open `http://<EC2-PUBLIC-IP>:9090/OnlineEventManagement/` showing the Online Event Management homepage.

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q2.1: Tomcat running successfully, but cannot access via EC2 Public IPv4 on port 9090:
  - Security Group Changes: Go to AWS Console -> EC2 -> Instances -> Security -> Security Groups -> Edit Inbound Rules -> Add Rule: Custom TCP, Port Range: 9090, Source: Anywhere-IPv4 (0.0.0.0/0) -> Save Rules.
  - Verification: Run `sudo ss -tulnp | grep 9090` or `curl http://localhost:9090` on EC2 to verify Tomcat is active locally. Check EC2 OS firewall `sudo ufw status`.
Q2.2: HTTP 404 error accessing `http://<EC2-Public-IP>:9090/OnlineEventManagement/`:
  - Reasons:
    1. WAR file name does not match `/OnlineEventManagement/` (e.g. deployed as `OEMS-1.war`, which creates path `/OEMS-1/` instead).
    2. WAR file failed to unpack in `/var/lib/tomcat9/webapps/`.
    3. `web.xml` welcome-file-list is missing `index.jsp`.
  - Troubleshooting: Check Tomcat logs: `sudo tail -n 100 /var/log/tomcat9/catalina.out`. Verify folder exists in `/var/lib/tomcat9/webapps/OnlineEventManagement`.
Q2.3: `mvn clean package` does not generate WAR in target directory:
  - Reasons:
    1. `<packaging>war</packaging>` is missing or set to `jar` in `pom.xml`.
    2. Missing `src/main/webapp` or `WEB-INF/web.xml`.
    3. Maven build failed due to compilation errors or dependency download failures.
  - Troubleshooting: Check Maven console error messages. Run `mvn clean package -X` for debug output. Check `pom.xml` build packaging tag.

  Open browser: http://localhost:8085
  Credentials:

4. Browser: Show Nginx "Welcome to nginx!" page opening via the Minikube URL.
5. Browser: Show Nagios Core web interface (`http://localhost:8085`), click **Hosts** and **Services** in the left menu to show monitoring status dashboard.

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q4.1: Increasing replicas from 2 to 5 causes some Pods to remain in "Pending" state:
  - Reasons: Insufficient CPU or memory resources on the Minikube node; node reached maximum pod limit; resource quotas exceeded.
  - Troubleshooting:
    Run `kubectl describe pod <pending-pod-name>` and inspect the "Events:" section (look for `FailedScheduling: 0/1 nodes are available: insufficient cpu/memory`).
    Increase minikube resources: `minikube start --cpus=4 --memory=8192`.
Q4.2: Customer cannot access application through browser even though Pods are running:
  - Reasons: Minikube runs inside a Docker VM, so NodePort is not automatically reachable directly on localhost unless bridged or port-forwarded.
  - Solution: Run `minikube service nginx-service --url` to obtain the correct accessible cluster IP:NodePort, or run `kubectl port-forward svc/nginx-service 6060:6060` to access via `http://localhost:6060`.
Q4.3: One of the application Pods crashes during booking; how does Kubernetes ensure replicas:
  - Explanation: The Kubernetes **Deployment Controller** and underlying **ReplicaSet** continuously maintain a reconciliation loop between the **Desired State** (replicas = 3) and the **Actual State**. When a pod crashes, the ReplicaSet detects the actual running count is 2 (less than 3) and automatically schedules and spins up a new replacement pod immediately.
Q4.4: Commands to verify Nagios status and configuration:
  - Check container: `docker ps -f name=nagios4`
  - Check container logs: `docker logs nagios4`
  - Verify inside container: `docker exec -it nagios4 /usr/local/nagios/bin/nagios -v /usr/local/nagios/etc/nagios.cfg` (verifies configuration syntax without errors).

Q1. Docker Compose – Online Boutique Store [25 Marks]
--------------------------------------------------------------------------------

OVERVIEW:
Run MySQL backend (port 3306) and Tomcat web server (port 8080) in separate containers with persistent volume using Docker Compose.

STEP 1: Create a dedicated directory
Execute in terminal:
  mkdir -p ~/set2_task1
  cd ~/set2_task1

STEP 2: Create the Docker Compose file (docker-compose.yml)
Execute in terminal:
  cat << 'EOF' > docker-compose.yml
version: '3.8'

services:
  mysqldb:
    image: mysql:8.0
    container_name: boutique-mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: boutiquestore
      MYSQL_USER: boutique_user
      MYSQL_PASSWORD: boutique_pass
    ports:
      - "3306:3306"
    volumes:
      - boutique_db_data:/var/lib/mysql
    networks:
      - boutique-network

  tomcat:
    image: tomcat:9.0-jdk11-openjdk-slim
    container_name: boutique-tomcat
    restart: always
    ports:
      - "8080:8080"
    environment:
      - DB_HOST=mysqldb
      - DB_PORT=3306
      - DB_NAME=boutiquestore
    depends_on:
      - mysqldb
    networks:
      - boutique-network

volumes:
  boutique_db_data:
    driver: local

networks:
  boutique-network:
    driver: bridge
EOF

STEP 3: Start the containers
Execute in terminal:
  docker compose up -d

STEP 4: Verify running containers and volume
Execute in terminal:
  docker compose ps
  docker volume ls | grep boutique_db_data
  docker compose logs mysqldb
  docker compose logs tomcat

STEP 5: Test MySQL Connectivity and Persistent Data
Execute in terminal:
  docker exec -it boutique-mysql mysql -u root -prootpassword -e "USE boutiquestore; CREATE TABLE IF NOT EXISTS products (id INT PRIMARY KEY, name VARCHAR(50), price INT); INSERT INTO products VALUES (1, 'Silk Saree', 1500); SELECT * FROM products;"

STEP 6: Access Tomcat through Web Browser
  Open browser: http://localhost:8080/

WHAT TO SHOW TO MAM:
1. Terminal: Run `docker compose ps` showing `boutique-mysql` (port 3306) and `boutique-tomcat` (port 8080) both running with status "Up".
2. Terminal: Show persistent volume `boutique_db_data` created using `docker volume inspect set2_task1_boutique_db_data`.
3. Terminal: Show MySQL query output containing the products table and records.
4. Browser: Open `http://localhost:8080/` showing the Apache Tomcat landing page.

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q1.1: Configure port mappings and custom Docker network:
  - In `docker-compose.yml`, define `ports: ["8080:8080"]` for tomcat and `ports: ["3306:3306"]` for mysql.
  - Define custom bridge network `boutique-network` under `networks:`. Both containers share this network, allowing Tomcat to reach MySQL using the service name `mysqldb` via Docker's embedded DNS.
Q1.2: Why customer registration/product data is lost when MySQL is recreated, and how volumes preserve it:
  - Containers are ephemeral; by default, any data written inside container filesystem `/var/lib/mysql` is destroyed when the container is deleted.
  - Solution: Configure a named volume (`boutique_db_data:/var/lib/mysql`) in `docker-compose.yml`. Even if container is stopped and removed (`docker compose down`), the volume persists on the host disk and mounts back on `docker compose up`.
Q1.3: Connection Refused on http://localhost:8080 troubleshooting:
  - Check if Tomcat container is running: `docker compose ps`
  - Check container logs for boot crashes: `docker compose logs tomcat`
  - Verify host port mapping: Ensure no other service occupies port 8080 on the host (`netstat -tulnp | grep 8080`).
  - Safely stop and remove containers: `docker compose down` (or `docker compose down -v` if wiping volumes).

Q2. Jenkins Pipeline for a Maven Web Project with Webhooks [25 Marks]
--------------------------------------------------------------------------------

OVERVIEW:
Build `https://github.com/haleema91/LAB-INTERNAL-II-OBS.git` using Jenkins Pipeline, deploy to Tomcat, and configure GitHub Webhook auto-trigger.

STEP 1: Open Jenkins and Create New Pipeline Project
1. Open `http://localhost:8080`.
2. Click **New Item** -> Name: `OnlineBoutiqueStore` -> Select **Pipeline** -> Click **OK**.

STEP 2: Configure Webhook Build Trigger
1. In the project configuration, under **Build Triggers**:
   - Check the box: **GitHub hook trigger for GITScm polling**.

STEP 3: Configure GitHub Webhook (in GitHub Repo Settings)
1. Go to your GitHub repository -> **Settings** -> **Webhooks** -> **Add webhook**.
2. Payload URL: `http://<YOUR-JENKINS-IP>:8080/github-webhook/`
3. Content type: `application/json`
4. Which events would you like to trigger this webhook? Select: **Just the push event**.
5. Click **Add webhook**.

STEP 4: Pipeline Script
In Jenkins Pipeline configuration, paste the following script:

pipeline {
    agent any

    tools {
        maven 'Maven'
    }

    stages {
        stage('Clone Repository') {
            steps {
                git branch: 'main', url: 'https://github.com/haleema91/LAB-INTERNAL-II-OBS.git'
            }
        }

        stage('Maven Clean & Compile') {
            steps {
                sh 'mvn clean compile'
            }
        }

        stage('Run Tests') {
            steps {
                sh 'mvn test'
            }
        }

        stage('Package WAR') {
            steps {
                sh 'mvn package'
            }
        }

        stage('Deploy to Tomcat') {
            steps {
                echo 'Deploying WAR to Tomcat webapps...'
                // Copies built war to Tomcat webapps directory:
                sh 'cp target/*.war /var/lib/tomcat9/webapps/OnlineBoutiqueStore.war || true'
            }
        }
    }
    post {
        always {
            archiveArtifacts artifacts: 'target/*.war', allowEmptyArchive: true
        }
    }
}

STEP 5: Create Jenkins Pipeline View
1. Click `+` tab on Jenkins main dashboard -> Select **Pipeline View**.
2. Name it `Boutique-Pipeline-View` -> Select `OnlineBoutiqueStore` as initial job -> Click **OK**.

WHAT TO SHOW TO MAM:
1. GitHub Webhook settings page showing green checkmark for `http://<jenkins-url>:8080/github-webhook/`.
2. Jenkins **Pipeline View / Stage View** showing all stages (Clone -> Clean & Compile -> Test -> Package -> Deploy) in green.
3. Jenkins **Console Output** showing `[INFO] BUILD SUCCESS` and `Finished: SUCCESS`.
4. Tomcat webapps showing deployed `OnlineBoutiqueStore.war`.

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q2.1: Maven command to remove previously generated build files before building:
  - Command: `mvn clean` (deletes the entire `target/` directory).
Q2.2: Where to provide repository URL in Jenkins pipeline for a private repo:
  - In the `git` or `checkout scm` step inside the `stage('Clone')`:
    `git credentialsId: 'github-cred-id', url: 'https://github.com/username/repo.git'`
    Credentials must be pre-configured in Jenkins -> Manage Jenkins -> Credentials.
Q2.3: Application building successfully, but WAR file not generated:
  - Command: Run `mvn package` (or `mvn clean package`). Ensure `<packaging>war</packaging>` is defined in `pom.xml`.

Set up Nagios using Docker, start web interface, demonstrate host & service monitoring status, and troubleshoot connection and host discovery issues.

STEP 1: Run Nagios Core in Docker
Execute in terminal:
  docker run -d --name nagios-monitor -p 8080:80 jasonrivers/nagios:latest

STEP 2: Verify Nagios Container is Running
Execute in terminal:
  docker ps -f name=nagios-monitor
  docker logs nagios-monitor

STEP 3: Access Nagios Web Interface
1. Open web browser: `http://localhost:8080` (or `http://<ec2-ip>:8080`)
2. Enter default login credentials:
   - Username: `nagiosadmin`
   - Password: `nagios`

STEP 4: Demonstrate Monitoring Status and Status Meanings
1. In the left navigation pane under **Current Status**:
   - Click **Hosts**:
     Shows `localhost` host status as **UP** (highlighted in Green).
   - Click **Services**:
     Shows critical service checks for localhost:
     * HTTP: OK (Green)
     * PING: OK (Green)
     * SSH: OK (Green)
     * Root Partition: OK (Green)
     * Current Load: OK (Green)
     * Total Processes: OK (Green)
2. Explanation of Status Indicators:
   - **UP / OK (Green)**: Host/Service is healthy and operating within threshold parameters.
   - **WARNING (Yellow)**: Service is operational but has crossed warning threshold (e.g. high CPU load or 80% disk full).
   - **CRITICAL (Red)**: Service has failed, crashed, or crossed critical limit (e.g. service unresponsive, 95% disk full).
   - **UNKNOWN (Orange)**: Nagios plugin cannot determine status (e.g. check plugin missing or timed out).
   - **PENDING (Grey)**: Service has recently been registered and has not undergone its first active check cycle.

WHAT TO SHOW TO MAM:
1. Browser: Nagios Web Dashboard at `http://localhost:8080/nagios/`.
2. Navigation: Click **Hosts** to display `localhost` marked **UP** in green.
3. Navigation: Click **Services** to show the table of services (HTTP, PING, SSH, Load, Disk) with Status **OK** in green.
4. Terminal: Show `docker ps` displaying `nagios-monitor` container running on port 8080.

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q3.4: Web interface displays "Unable to connect to Nagios process":
  - Root Cause: The core Nagios daemon (`/usr/local/nagios/bin/nagios`) has stopped running or crashed, even though the Apache web server hosting the PHP/CGI interface is still up.
  - How to resolve:
    1. Check Nagios service status inside container:
       `docker exec -it nagios-monitor service nagios status`
    2. Start the Nagios service:
       `docker exec -it nagios-monitor service nagios start`
    3. Check for stale lock file `/usr/local/nagios/var/nagios.lock` and remove it if process died abruptly.
    4. Inspect `/usr/local/nagios/var/nagios.log` for segmentation faults or configuration load errors.
Q3.5: Added a new host in Nagios, but it is not appearing on the web interface:
  - How to check:
    1. Pre-flight verification: Run the Nagios configuration pre-flight check to test for syntax errors:
       `docker exec -it nagios-monitor /usr/local/nagios/bin/nagios -v /usr/local/nagios/etc/nagios.cfg`
    2. Confirm host config inclusion: Verify that `cfg_file` or `cfg_dir` directive in `/usr/local/nagios/etc/nagios.cfg` points to your newly created host file.
    3. Restart/reload daemon: Nagios does not automatically reload on file edits. You must reload or restart:
       `docker exec -it nagios-monitor service nagios reload` (or `restart`).
    4. Contact / Group permissions: Ensure the host definition assigns `contact_groups` that include `nagiosadmin`, otherwise the user cannot see it in the UI due to CGI authorization filters (`cgi.cfg`).

Q4. AWS EC2 – Launch and Deploy a Web Application [25 Marks]
--------------------------------------------------------------------------------

OVERVIEW:
Deploy Maven Web Application (https://github.com/savram674/BookBank.git) on an Ubuntu EC2 instance, build Docker image, start container, and access via EC2 Public IPv4.

STEP 1: Launch EC2 Instance & Configure Security Group
1. AWS Console -> EC2 -> Launch Instance.
2. Name: `BookBank-Server`
3. AMI: Ubuntu Server 22.04 LTS (HVM), SSD Volume Type.
4. Instance Type: t2.micro (Free Tier eligible).
5. Key Pair: Select existing key or create new `.pem` key.
6. Network / Security Group Rules:
   - Allow SSH: Port 22 | Source: 0.0.0.0/0
   - Allow Custom TCP: Port 8080 | Source: 0.0.0.0/0
   - Allow HTTP: Port 80 | Source: 0.0.0.0/0

STEP 2: Connect to EC2 via SSH
  ssh -i your-key.pem ubuntu@<EC2-PUBLIC-IP>

STEP 3: Install Docker and Git on EC2
Execute on EC2:
  sudo apt update -y
  sudo apt install -y docker.io git
  sudo systemctl start docker
  sudo systemctl enable docker
  sudo usermod -aG docker ubuntu
  # Apply new group membership:
  newgrp docker

STEP 4: Clone the BookBank GitHub Repository
Execute on EC2:
  cd ~
  git clone https://github.com/savram674/BookBank.git
  cd BookBank

STEP 5: Create a Multi-Stage Dockerfile to Build and Run BookBank
Execute on EC2:
  cat << 'EOF' > Dockerfile
# Stage 1: Build Maven WAR
FROM maven:3.8.4-openjdk-17-slim AS builder
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN mvn clean package -DskipTests

# Stage 2: Deploy to Apache Tomcat
FROM tomcat:9.0-jdk17-slim
WORKDIR /usr/local/tomcat/webapps/
RUN rm -rf /usr/local/tomcat/webapps/ROOT
# Copy generated war as ROOT.war for direct root context access
COPY --from=builder /app/target/BookBank.war ./ROOT.war
EXPOSE 8080
CMD ["catalina.sh", "run"]
EOF

STEP 6: Build the Docker Image
Execute on EC2:
  docker build -t bookbank-app:v1 .

STEP 7: Run the Application Container
Execute on EC2:
  docker run -d --name bookbank-container -p 8080:8080 --restart=always bookbank-app:v1

STEP 8: Verify Container and Access Application
Execute on EC2:
  docker ps
  docker logs bookbank-container
  curl http://localhost:8080

STEP 9: Access in Browser
  Open browser: http://<EC2-PUBLIC-IP>:8080/
  (or http://<EC2-PUBLIC-IP>:8080/login.jsp)

WHAT TO SHOW TO MAM:
1. AWS EC2 Console: Show the Running Ubuntu instance details with its Public IPv4 address.
2. Security Groups: Show the Inbound Rule permitting Port 8080 from 0.0.0.0/0.
3. Terminal on EC2: Run `docker ps` showing `bookbank-container` mapped to `0.0.0.0:8080->8080/tcp` with status "Up".
4. Web Browser: Open `http://<EC2-PUBLIC-IP>:8080/` showing the BookBank application (index / login JSP page).

SCENARIO-BASED ANSWERS FOR VIVA / LAB EVALUATION:
Q4.5: Steps to install Maven on Ubuntu and Amazon Linux EC2:
  - On Ubuntu EC2:
    `sudo apt update -y`
    `sudo apt install -y openjdk-17-jdk maven`
    Verify: `mvn -version`
  - On Amazon Linux 2023 EC2:
    `sudo dnf update -y`
    `sudo dnf install -y java-17-amazon-corretto maven`
    Verify: `mvn -version`
Q4.6: Which EC2 feature automates deployment of index.html whenever instance restarts:
  - For Initial Launch: **EC2 User Data (User Data shell script)** under Advanced Details during instance launch automatically executes scripts with root privileges on the first boot.
  - For Every Instance Restart / Reboot:
    1. **EC2 User Data with Cloud-init MIME multi-part script**: Configure cloud-init `runcmd` with `[always]` frequency so it executes on every reboot.
    2. **Crontab `@reboot`**: Add an entry to root's crontab:
       `@reboot /bin/bash /home/ubuntu/deploy.sh`
    3. **Systemd Service Unit**: Create a custom systemd service in `/etc/systemd/system/auto-deploy.service` with `WantedBy=multi-user.target` that executes the deployment script on every system startup.
